# Design System: Antigravity Manager

## Overview

**Creative North Star: "Signal Blue workspace"**

Signal Blue combines cool neutral surfaces, clear blue actions and restrained status colors with consistent typography, spacing and control proportions. The interface supports frequent desktop work through stable density, readable metadata and predictable interactions.

The design system is implemented with the existing Radix and Tailwind component
stack. Product workflows and constraints remain in [PRODUCT.md](PRODUCT.md).

**Key Characteristics:**

- Signal Blue in light and dark themes.
- Geist with explicit CJK fallbacks and Geist Mono for measured data.
- A 4px spacing base and 28 / 36 / 40px controls.
- Flat content surfaces and scoped feature layouts.

## Colors

The normative values above map directly to CSS properties in
[src/styles/global.css](src/styles/global.css). Unprefixed entries describe light
mode; each `dark-` entry is the corresponding property under `.dark`.

- Primary blue marks the main action, selection and keyboard focus. Dark mode
  uses a lighter blue with dark text on filled actions.
- Background, sidebar, card and popover form distinct surface levels.
- Muted foreground remains readable on both the page and cards.
- Info, success, warning and destructive each have a foreground role; info,
  success and warning also have soft surface and border roles.
- Chart colors reuse the same semantic roles. Never infer state from color alone.

## Typography

Use the bundled variable Geist font for UI and Geist Mono for code, addresses and
measured values. The full sans stack includes Segoe UI, PingFang SC, Microsoft
YaHei and Noto Sans CJK SC before the generic fallback. Fonts are loaded locally.

- Page titles: 30 / 38px, weight 600, tracking -0.025em. At 760px and below:
  24 / 32px.
- Card titles: 16 / 24px, weight 600, tracking -0.01em.
- Body and controls: 14 / 22px.
- Secondary labels and quota data: 12 / 20px. Use tabular numerals for measured data.
- Heading dimensions never constrain the width of unrelated text containers.

## Layout

Use a 4px spacing base: 4, 8, 12, 16, 20, 24 and 32px. Main page containers have
32px padding and a 1480px maximum width. Padding becomes 24px below 1200px and
16px at 760px and below. Section gaps are 24px; account grid gaps are 16px.

The expanded sidebar is 224px wide. Its collapsed and narrow-window widths are
64px. Navigation rows are 40px high. Account grids use one column below 1200px;
tool cards use one column below the existing 1280px breakpoint. Tool card headers,
status, summaries and actions share grid rows so optional details do not shift
primary actions.

Components express layout, spacing and responsive behavior with Tailwind
utilities. Global CSS owns theme values, fonts, typography tokens, the shared
container utility and browser defaults.

## Elevation & Depth

Account cards, controls and summaries use borders and surface tones without
resting shadows. Menus and dialogs retain the existing offset shadow vocabulary
for overlays. Focus uses a visible 2px ring and offset. No decorative halo is
required to convey state.

## Shapes

Use 4px for checkboxes and small labels, 6px for compact controls and quota rows,
8px for standard buttons and account cards, and 12px for dialogs and menus.
Avatar and progress-track circles remain circular.

## Components

- **Controls:** default minimum height 36px, compact account actions 28px, large
  controls 40px. Coarse-pointer actions grow to at least 40px. Preserve disabled,
  busy and focus states. Button variants and sizes belong to the shared Button
  component: use `xs` / `icon-xs` for compact actions, `default` / `icon` for
  standard actions and `lg` / `icon-lg` for large actions.
- **Tabs:** 36px triggers inside a 44px container with 4px padding. Horizontal
  overflow remains available; no vertical scrollbar appears. Coarse-pointer
  tabs use a 48px container around 40px triggers.
- **Checkboxes:** 16px visual square with an enlarged 24px pointer target.
- **Account cards:** 20px body inset, 12px row padding and a 56px minimum footer.
  At narrow widths, card insets become 16px and footer actions wrap.
- **Use menu:** opens through click, Enter, Space or ArrowDown. Hover does not
  open it; pointer exit does not close it. Escape restores focus to the trigger;
  outside click dismisses it. Existing switching and launch actions are retained.
- **Upstream proxy:** the label and validation message retain full field width.
  Reveal and Save form an action group with an 8px gap.
- **Tool configuration:** primary actions align across sibling cards, including
  when OpenCode connection details expand.
- **Motion:** 150ms ease-out for control state transitions; honor reduced motion.

The [design extensions](.impeccable/design.json) contain renderable primitives,
motion, elevation and breakpoint metadata.

Shared primitives own their visual variants through component classes and CVA
when a component exposes real variants. Feature layouts use local Tailwind
utilities, including subgrid for aligned tool-card actions. Keep `data-slot` as
an explicit component-part hook. Do not style business components through
global slot or ARIA-role selectors, or infer parts from sibling position.

## Do's and Don'ts

- Do use semantic color tokens for surfaces, text and status.
- Do retain 12px horizontal padding inside model hover rows.
- Do keep page-specific dimensions inside their owning component.
- Do open the account Use menu by click or keyboard, and close it with Escape or an outside click.
- Don't reintroduce hover opening for the account Use menu.
- Don't apply account icon widths to other page headers.
- Don't collapse input errors or adjacent actions into an unspaced inline row.
- Don't let optional tool details move sibling primary actions out of alignment.
