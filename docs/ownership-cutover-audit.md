# Ownership Cutover Audit

Current readiness reference, 2026-09-27. The inventory and blocking matrix below preserve the iteration 18 source-audit baseline; subsequent resolutions are recorded separately. This is not an implementation completion claim.

## Result

**Remote bootstrap is implemented; production cutover is not release-validated.** Cloud-account operations migrated in iterations 7鈥?7 do not cover the whole application profile. Embedded remains the default; the remote startup composition is available as an advanced restart-only preference. The audit identifies broader subsystems; the resolution sections describe implemented adapter migrations.

## Configuration resolution (iteration 19)

The configuration, API-key generation and binary-patch configuration-reader rows in the baseline matrix are resolved at the adapter boundary. Runtime/proxy configuration has serialized selected-owner reads/writes and owner-only gateway application. API keys and upstream URLs use explicit reveal/write operations, with presence metadata in normal snapshots. Binary patch preparation reads the current owner snapshot. Desktop preferences use independent versioned Electron user-data storage with one-time legacy seeding. Effective alert policy retains its existing SQLite source through a separate selected-owner API, without promoting stale GUI values or introducing dual writes.

These resolutions do not activate remote ownership. Desktop lease/bootstrap and gateway lifecycle composition, legacy accounts, audit/thought workers and exports/events, OpenCode and packaged native delivery remain blockers. The inventory counts below are historical baseline evidence, not a fresh clean audit. Focused tests cover private endpoint parity, unavailable-owner behavior, input/secret bounds, configuration drain and desktop settings interactions; native SQLite, installers and live providers remain unverified.

## Legacy account resolution (iteration 20)

The legacy-account baseline row is resolved at the adapter boundary. Existing snapshot creation/listing, switch/restore, deletion and identity history/binding policy is extracted into Node services and exposed through strict selected-owner routes. Normal metadata excludes backup paths and credential contents. The unused raw database backup/restore renderer actions are removed end to end; owner-internal primitives and durable formats remain. Existing same-email replacement and target-specific SQLite/keyring injection behavior remain the owner policy. All legacy operations join admission/drain, with serialized mutations. Electron retains folder-opening presentation only.

Real private-endpoint tests cover safe snapshot parity, restore completion and identity metadata, failure without local fallback, invalid input and closed admission/drain. Existing legacy switch tests retain collision, concurrency and credential-target regression coverage. Native SQLite/keyring and installer/provider evidence remain separate gates. Audit/thought, OpenCode, desktop bootstrap/lease and native delivery still block cutover; the baseline inventory has not been rescanned to claim whole-project readiness.

## OpenCode resolution (iteration 21)

The OpenCode baseline row is resolved at the adapter boundary. Status, sync, redacted preview, restore, clear and dedicated-key revocation use one selected owner. Existing external plugin v3 account projection, configuration backup/recovery and key storage remain unchanged. Refresh grants stay in owner-local plugin file effects; no credential handoff or Manager-side refresh mechanism is added. All operations are serialized and drained, including status installation detection. Transport responses and errors are bounded and sanitized. Public IPC error handling for configuration, legacy accounts and OpenCode excludes raw diagnostics and preserves closed categories.

Real private-endpoint and renderer-middleware tests cover parity, grant/key exclusion, model tables above the ordinary request cap, backup recovery, revocation, disconnection without fallback and read/write admission/drain. Audit/thought, desktop bootstrap/lease and packaged native delivery remain blockers; Electron still selects embedded ownership. This resolution does not constitute a clean whole-project rescan or native release evidence.

## Audit file-export progress (iteration 22)

The desktop body-save path delegates to the selected audit file owner. Large exports stream directly to the main-selected destination, without increasing control-RPC limits or returning body content/paths to React. Atomic temporary-file replacement preserves existing output on pre-commit read/write failure. Ordinary audit queries, paging/search, statistics and delete/clear/repair use the selected audit owner with bounded responses and serialized admission/drain. Existing administrative record IDs remain valid; JSON-expanded pages preserve deferred chunks through the cursor. Window events use a bounded epoch/cursor journal with reset on overflow/restart and stale-owner reply suppression. Thought summaries, single-record detail, statistics and maintenance use their selected owner; explicit Thought/cURL content uses bounded temporary capabilities described in [architecture](architecture.md#runtime-topology). Remote failures never fall back to a local reader. Terminal store admission, body/SSE/hydration drain and no-recreation guards now run during core and desktop shutdown, including with the gateway off. Failed closure retains core profile ownership. The remote IPC recorder preserves the existing model/session and sanitized error contracts through bounded metadata and body transfer; whole-application selection remains cutover work. Full-core native shutdown, installers, other platforms and whole-application cutover remain unverified.

## Desktop bootstrap resolution (iteration 23)

Desktop startup resolves a restart-only user-data preference before acquiring a profile lease or
initializing owner security/SQLite. Remote startup verifies compatible, ready management identity
against the current profile owner and selects all migrated adapters before renderer admission.
Epoch-pinned requests reject replacement owners; failure never enters embedded recovery.
Desktop shutdown drains renderer admission and polling, preserves external/race-winning cores and
waits for its own launched core's terminal lease release. Embedded remains the production default.

Windows Node 24 process acceptance passed the built standalone core, actual SQLite capture/reopen,
external attachment and terminal lease disappearance. The presentation composition uses fail-fast
SQLite/keytar/Worker sentinels; the core uses a disposable keytar substitute. This does not establish
real Electron window behavior, real OS keyrings, native installer delivery or other platforms.
The baseline matrix below is historical; remaining release gates require a fresh whole-project
rescan and platform acceptance before changing the default selector.

## Evidence and scope

The Node-compatible IPC recorder drains admitted desktop handlers and parent completion before
store teardown. Its explicit remote adapter now transfers redacted input/output in bounded chunks
and restores owner-local parent/attempt/Thought context on private RPC calls. Private-endpoint
tests use substituted persistence; a separate Windows Node 24 service check passed prepared-body
SQLite writes/redaction and complete persisted reopen, terminal close and Thought/signature reopen
in an isolated temporary home. Together these cover transport and native services separately.
Private-endpoint checks now preserve long session/model fields and the existing sanitized error
snapshot. Capacity checks cover the three 100 MiB logical boundaries; native SQLite separately
verifies oversized-prefix persistence and accounting after reopen. Whole-core process shutdown,
installed desktop selection, process memory under load and other platforms remain unverified;
embedded remains the default startup mode.

- Current renderer RPC routers, main/preload entry points, owner startup/shutdown, lazy database/worker initialization and update preference storage were inspected directly.
- This is static source evidence. It does not validate native binaries, packaged resource discovery, real OS keyrings, live providers or every platform-specific branch. Raw scan files are temporary and are removed after generating this reference.

## Configuration responsibilities

- **Owner behavior:** proxy configuration/API key, routing and model policy, credential-related account settings, monitor/warmup settings, quota/credit alert policy, and executable/launch policy consumed by owner switches.
- **Desktop effects/preferences:** language/theme, layout/filter/sort/model visibility, tray visibility, OS auto-start registration, export chooser preferences and update-check preferences.
- **Shared read-only inputs:** early observability consent and machine information. A shared file location does not authorize multiple writers or independent stale caches.
- The combined `gui_config.json` is still the existing durable contract. Define one writer and explicit effect/application boundaries before deciding whether any future format separation is needed. This audit does not split or migrate that format.

## Startup and shutdown conclusions

Core ownership ordering is coherent for the migrated capabilities. Cloud DB and audit/thought worker implementations initialize lazily, which means importing their modules is not equivalent to opening their databases. Desktop RPC calls to those workers are nevertheless persistence operations and remain blockers in remote mode.

Desktop shutdown is intentionally bounded by its existing three-second forced exit. It drains the migrated monitor, local-import, presentation and switch work, then stops the embedded gateway. It does not yet define remote attach/detach behavior or drain the broader legacy account/config/sync surfaces. The desktop lease is currently held for process lifetime; the explicit core lease release remains last after successful teardown.

## Required implementation order

1. Make combined configuration and API-key generation owner-aware; preserve desktop OS/UI effects and durable semantics.
2. Migrate legacy local-account snapshot/restore/switch/identity operations with credential-safe transport and lifecycle drain.
3. Migrate gateway audit/thought stores, events and export/clipboard reads to the owner, preserving resource and payload limits.
4. Re-audit startup, machine operations, callbacks and shutdown against these completed boundaries.
5. Implement explicit core attachment/startup, owner selection and reversible desktop cutover.
6. Validate isolated native Node SQLite/keyring and packaged Windows/macOS/Linux install/upgrade/recovery behavior, plus live provider flows. These are release gates, not inferred passes.
